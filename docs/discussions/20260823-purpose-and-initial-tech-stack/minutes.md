# 議事録

discovery.md の前提をもとに、エージェントと詳細を詰めた。

## データモデルと UX

「タイトル」と「読み終わった巻数」を保存する、という要件に対し、
「マンガ喫茶」「購入済み」のようなカテゴリでの分類方法を確認した。
結果、単純なタグ分類ではなく、グループを作りその中へアイテムを追加する UX を採用した。

## 利用者範囲

Google アカウントを持つ任意のユーザーを許可するかを確認した。
認証さえ通れば誰でも使える状態にするが、利用の呼びかけや広報は行わない、という結論になった。

## 静的ファイル配信方式（不採用案あり）

当初、フロントエンドの静的ファイル配信に Cloud CDN を使う案を検討した。
Firebase ではなく Google Cloud 側のサービスに寄せたいという意図からの提案だったが、
0 円運用を優先する観点から、Cloud Run から SPA と API を同一オリジンで配信する方式に変更した。
Cloud CDN は追加のコストと構成要素を持ち込むため、この規模のアプリでは不要と判断した。
この案は proposal.md には採用されていない。

## スコープ

アイテムを別グループへ移動する機能は初期スコープ外とすることを確認した。

## 保存項目の確認

ユーザー情報としてプロフィール画像（URL）も保存することを確認した。
Firestore TTL は課金対象となるため使用しない方針を確認した。

## 残りの技術選定

エージェントから未決事項について問い合わせ、答えられる範囲で以下を確定した。

- Go・React は開発開始時点の最新安定版、Node.js は LTS 版を使用する。
- フロントエンドはパッケージマネージャーに pnpm、ビルドツールに Vite、言語に TypeScript を使用する。
- 状態管理とフォームライブラリは保留（後続トピックで決定）。
- CSS は Tailwind CSS v4（セマンティックトークン使用）、UI コンポーネントは shadcn/ui を使用する。
- アイテムのタイトルは 100 文字以下。アイテム一覧にはページネーションが必要。
- API の統一エラー形式、画面構成と操作フロー、テスト戦略は後続トピックで決定する（この時点では保留）。
- Infrastructure as Code には Terraform を採用する。
- Firestore のインデックス設計は後から検討する。
- バックアップ・復旧・データエクスポートは実施しない。
- カスタムドメインは使用しない想定。

これらの回答を proposal.md に反映した。
