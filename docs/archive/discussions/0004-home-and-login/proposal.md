# ホーム・ログインと共通レイアウト・ページ一覧

## ステータス

提案。決定ではない。エラー状態（API失敗時などの表示）は別トピックへ先送りする。

## 背景

[purpose and initial tech stack](../0001-purpose-and-initial-tech-stack/proposal.md) では、
Google Identity Services を用いた認証フローと Firestore データモデル（`users/{sub}/groups/{groupId}/items/{itemId}`）を確定させた一方、
「画面構成と操作フロー」は後続トピックへ保留していた。本提案はその後続トピックとして、共通レイアウト、ホームページ、
ナビメニュー、グループ・アイテムの CRUD ページ、URL 設計、空状態・ローディング状態を定める。

## 共通レイアウト

ホームページを除く全ページで使用する。

- ヘッダ: タイトル（左） + アカウント画像（右）。
- アカウント画像をタップすると、右からナビメニューが表示される。
- フッター: アプリ名のみを控えめに表示する（著作権表記など他の情報は含めない）。

## ナビメニュー

ヘッダのアカウント画像タップで右からスライド表示する。

- グループ一覧ページへのリンク
- ログアウト

## ホームページ（`/`）

共通レイアウトを使用しない、独立した画面とする。

- マウント時、認証状態確認（`GET /api/me`）の応答待ちの間はローディング表示とする。
- **未認証**: タイトル + ログインボタン。ログインボタンをタップすると、専用の `/login` ページへ遷移せず、
  その場で Google Identity Services によるログインを起動する。
- **認証済み**: タイトル + アカウント情報（画像・名前） + グループ一覧ページへのリンク + ログアウトボタン。

認証済みホームにグループ一覧へのリンクとログアウトボタンを直接置くのは、共通レイアウトを使用しないホームページに
ナビメニューを開く起点がなく、かつアプリの主目的（グループ管理）へのアクセスに一手間かけたくないための設計である。

## ページ一覧と URL 設計

Firestore のデータモデルのネスト構造（グループの配下にアイテムがある）に合わせた URL 設計とする。
以下は全て共通レイアウトを使用する。

| パス | ページ | 補足 |
| --- | --- | --- |
| `/groups` | グループ一覧 | 取得中はローディング表示。0件なら一覧の代わりに空状態＋作成ページへの CTA ボタンを表示する。 |
| `/groups/new` | グループ作成 | 作成専用の別ページとする。編集ページとは共有しない。 |
| `/groups/:groupId/edit` | グループ編集 | 既存データ取得中はローディング表示。削除ボタンをタップすると独自の確認モーダルを表示し、確認後に削除する。 |
| `/groups/:groupId/items` | アイテム一覧 | 取得中はローディング表示。0件なら一覧の代わりに空状態＋作成ページへの CTA ボタンを表示する。 |
| `/groups/:groupId/items/new` | アイテム作成 | 作成専用の別ページとする。編集ページとは共有しない。 |
| `/groups/:groupId/items/:itemId/edit` | アイテム編集 | 既存データ取得中はローディング表示。削除ボタンをタップすると独自の確認モーダルを表示し、確認後に削除する。 |

## 削除の扱い

グループ・アイテムいずれも、削除操作は一覧ページではなく編集ページから行う。編集ページの削除ボタンをタップすると
独自実装の確認モーダルを表示し、ブラウザ標準の `confirm()` は使用しない。削除処理中はモーダル内のボタンをローディング状態にし、
多重送信を防ぐ。

グループ削除時に所属アイテムをまとめて削除する挙動（確認を求める点を含む）は
[purpose and initial tech stack](../0001-purpose-and-initial-tech-stack/proposal.md) で既に確定しており、
この確認モーダルがその確認手段にあたる。

## 空状態・ローディング状態

- **ホーム**: 認証状態確認中はローディング表示。
- **グループ一覧・アイテム一覧**: 取得中はローディング表示。0件の場合は一覧要素の代わりに空状態メッセージと、
  対応する作成ページへの CTA ボタンを表示する。
- **編集ページ**: 既存データ取得中はローディング表示。作成ページは初期値が空のため、ローディング状態は発生しない。

## スコープ外

- API 失敗時など、エラー状態の表示は別トピックで決定する。
- ログイン処理そのもの（Google Identity Services の呼び出し方法、ID Token の送信）は
  [purpose and initial tech stack](../0001-purpose-and-initial-tech-stack/proposal.md) で確定済みのため、本提案では扱わない。
