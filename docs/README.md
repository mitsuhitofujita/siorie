# docs/

未整理の意図を書き溜め、思いつきを実装し、やったことを現時点の仕様としてメモしておくための場所です。

```
docs/
├── intent/   未整理の意図（日本語・不確実、不完全、誤り、矛盾を含んでよい）
├── spec/     いま何がどうなっているか（英語・上書き）
└── log.md    やったことの時系列メモ（英語・追記のみ）
```

## intent/

私の意図や思いつきを、未整理のまま日本語で書き溜めます。
不確実、不完全、誤り、矛盾、理想を含んでいます。整合性や結論を求めません。
話題ごとに自由な名前の Markdown ファイルを作り、形式は決めません。

ここにある記述は、確定仕様や実装指示ではありません。
`/think` や `/build` では関連する記述を背景として読み、今回の依頼に沿って扱います。
保存を依頼されたら、曖昧さや矛盾を勝手に解消せずに記録し、AI の推測を私の意図として混ぜません。
実装した結果は `spec/` に反映し、元の意図を現在の仕様に合わせて書き換える必要はありません。

## spec/

システムの現況を、機能や領域ごとに一ファイルずつ英語で書きます。
常に最新の状態だけを書き、古い記述は消して上書きします。履歴は残しません。

思いつきを実装したら、その結果がどう動くかをここに反映します。
実装に向けて整理した未実装の仕様案や、未整理の意図は `intent/` に書きます。

## log.md

一回の作業（Issue 一件、または `/build` 一回）につき一見出しで、やったことを数行ずつ英語で追記します。
見出しは短い題と日付、Issue があればその番号です。
「何を変えたか」と、あれば「決めた理由を一言」だけで十分です。
振り返りや反省、困難の分析は書きません。

```markdown
## Item groups (2026-09-06, #12)
- A group is just a tag on items, no separate table.
- Chose tag over table because groups rarely need their own fields yet.
```

## 決めごと

この docs は、開発を止めてまで整えるものではありません。

仕様や作業記録の矛盾や古い記述に気づいても、その場で直せる範囲だけ直し、直せなければ log に一行だけ書いて先に進みます。
`intent/` の不確実さ、不完全さ、誤り、矛盾は修正や log への記録を必要としません。
文書同士のリンクや status や連番は管理しません。
検討の過程を逐一残す必要はありません。残したい意図は `intent/` に書きます。
